# Go2 三相机与背部方向标记：实现和复用经验

本轮让机械狗探索过程更容易观察：头部看前方，二号看身体和四腿，三号看全局位置；背部亮绿色箭头补足灰色机身与迷宫对比度不足的问题。[当前工作区](../../ros2_ws_go2_maze_20261107/README.md) · [真实图像与验收数据](../validation/2026-11-07-go2-three-cameras/README.md)

## 最终行为

| 观察入口 | 最终设置 | 观察重点 |
| --- | --- | --- |
| 一号 /camera/front/image | 原头部相机，720×540、20 Hz | 前方走廊与转弯后的视野 |
| 二号 /camera/chase/image | 1280×720、20 Hz，Go2 位置加固定世界偏移 (-1.2,-0.9,+3.5) m | 身体、腿部动作和转向 |
| 三号 /camera/overview/image | 1024×1024、10 Hz，世界中心上空 24 m 垂直俯视 | 完整迷宫与狗的全局位置 |
| 背部箭头 | 绿色 32×15 cm，深色描边，随 base_link 指向机头 | 在灰色背景中辨认位置与朝向 |

用户选择二号只随位置平移，保持固定世界方向。配置为 `follow_yaw=false`：狗转弯时，镜头不绕狗旋转；机体 roll/pitch 也不倾斜地平线。相机一直瞄准身体下方 0.1 m，便于观察腿部。与之相对，背部箭头随身体完整姿态运动，明确表示狗自身的前向。

三路是原生 Gazebo sensor 图像，经 ROS bridge 进入独立 RViz Image 窗格。一号在下方，二、三号在右侧上下排列，可拖动浮动、放大。帧率是仿真时间下的传感器配置，实际接收率受负载影响；三路共享仿真时钟并异步刷新。

## 让观察功能保持独立

两个观察模型静态、无碰撞、无关节；原生 system 插件只向二号相机模型写 PoseCmd。它读取 Go2 的真实位姿来观察，不向 Go2 写位姿、力、速度或关节目标。静态模型不进入原验收器使用的动态 top-level 模型位姿流。

绿色箭头直接作为 base_link 的 visual，RViz Xacro 与 Gazebo SDF 使用相同本地 Collada 资源。对比基线：移除新增 visual 后，两份模型 XML 规范化结果完全一致；原惯量、碰撞、关节、传感器和控制插件保持原值。原七个官方 mesh 与校验值也保留，新增标记单独说明来源。[隔离检查](../validation/2026-11-07-go2-three-cameras/visual-isolation.json)

图像不作为导航输入。在线 flood-fill 继续使用已知边界和在线发现的内部墙体，完整墙图仍只用于独立验收/绘图。观察 TF 目前以世界原点的 odom 为 parent；以后换里程计原点时要一起适配。

## 这轮排查中可复用的要点

1. **相机资源正确还不等于生成姿态正确。** ros_gz_sim/create 的默认 EntityFactory 位姿会覆盖 SDF model pose。必须显式传入生成位置/角度，并看实际图像；仅检查 SDF 和静态 TF 会漏掉“相机实际仍在原点”的问题。
2. **改变分辨率和 HFOV 时同步核对内参。** 复制头部相机的 lens/intrinsics 会覆盖新的焦距、中心点与缩放。两路新相机去掉旧内参，由 Gazebo 根据分辨率和 HFOV 生成，再核对实际 CameraInfo。
3. **读实际生效位姿。** 二号在 PostUpdate 读取 ECS 实际相机姿态发布 optical TF，而不把期望位置当作测量结果。再按时间对齐 Go2 odom 检查位置偏移、光轴和地平线。
4. **直播验证必须覆盖整个窗口。** 图像与跟随 TF 都要检查时间单调、窗口覆盖、最大间隔和相对最终 odom 的新鲜度，防止开头有帧、后半程已冻结仍报告通过。
5. **画面运动要与噪声区分。** 每 24×24 区域取均值后再比较场景变化，避免把传感器高斯噪声当作渲染跟随成功。
6. **保存 RViz 布局后还要重载。** 三个 Image dock 同时可见，并关闭 Hide Right Dock；检查首次打开与可见窗口重载，避免右侧两路被折叠。
7. **全景需要明显的机体标记。** 三号覆盖整个约 20 m 迷宫，狗本来就小。亮绿箭头与黑边提高颜色对比，又让二号固定世界方向下的转弯更直观；纯 visual 可避免额外质量/碰撞影响步态。

## 实测与证据范围

初始随航向模式、切换固定方向后的站立检查、固定方向的 90 秒走转，以及增加箭头后的 45 秒走转分别归档。固定方向 90 秒检查实际行走 11.867 m，航向范围 1.784 rad，最大位置跟随误差 0.02096 m；加箭头后的 45.084 秒检查同样通过。

带最终固定方向、三路图像与背部箭头的同一轮自主实例，随后完成整座迷宫并停稳。成功封存快照为 918.932 仿真秒、117.936 m，出口距离 0.709254 m，最终线速度 0 m/s。54,050 条原生位姿严格重放通过，几何碰撞/非法越界均为 0，最大总倾角 4.195°。[完整记录](../validation/2026-11-07-go2-three-cameras/accepted/status.json) · [严格重放](../validation/2026-11-07-go2-three-cameras/accepted/replay_audit.json)

这些是指定环境中的单轮结果，尚未做多种子统计。几何验收不是接触力测量；保留世界坐标里程计的仿真边界。历史失败用例的范围见原通关报告，不把本轮核心回归描述成整个历史测试集全绿。

## 复现入口

按工作区 README 构建六包，执行 `./run_go2_maze.sh` 即打开默认三窗格并自主起步。另一个同 domain/partition 终端运行 `python3 tools/check_go2_cameras.py <全新目录> --seconds 90 --require-motion` 做只读走转检查。完整自动验收使用 `./tools/run_checked_maze.sh`；它会在结束后关闭本轮实例并严格重放。仅站立用 `autonomous:=false`，关闭新增相机用 `observer_cameras:=false`。

背部标记由 `tools/generate_go2_back_marker.py` 同时生成两处相同 mesh；`generate_go2_model.py` 从 Xacro 保留该 visual。修改视觉资源后重构建并重新加载模型，检查原始相机画面、物理隔离和导航反馈。
